# Korean Copyediting and Anti-Slop Checklist (한국어 범용 윤문 체크리스트)

Use this 58-point checklist as the final quality gate across **Reports and Docs**, **Emails and Messages**, **Web UI and Dashboards**, **Rule Descriptions**, and **Tech Blogs**. Old signals stay on the list even when newer signals are stronger.

## Part 1: Universal Sentence and Punctuation Hygiene (모든 글 공통 8항목)

- [ ] **1. 가운데점(`·`, `ㆍ`) 0건**: 가운데점이 한 번도 나오지 않는가? 두 항목은 `및`이나 `과`, 여러 항목은 쉼표, 부가 정보는 괄호로 풀고, 한 줄에 몰아넣은 속성은 표의 행을 나눈다. `입·출력`, `온·오프라인` 같은 고정 복합어도 `입출력`, `온오프라인`으로 쓴다.
- [ ] **2. 엠대시(`—`)와 세미콜론(`;`) 제거**: 한국어 산문에서 잘 쓰지 않는 대시나 세미콜론을 쉼표, 괄호, 또는 두 문장으로 나눴는가? (2026년에도 Claude는 엠대시를 많이 쓴다.)
- [ ] **3. 소리 내어 읽기(호흡과 조사 과밀 점검)**: 한 문장 안에 조사(`~에서는 ~을 대상으로 ~를 모아 ~에 ~과 ~가...`)가 7개 이상 겹쳐 숨이 막히지 않는가?
- [ ] **4. 단문 스타카토 병합(문서 한정)**: 보고서와 설계 문서에서 접속사 없는 짧은 단문이 4개 이상 이어질 때, 인과와 대조 관계에 맞춰 `하지만`, `반면`, `따라서` 또는 연결어미(`~하며`, `~하되`, `~지만`)로 이었는가? 대화 답변과 메신저는 짧은 문장을 유지하되 한 문장에 단서를 겹치지 않았는가?
- [ ] **5. `~를 통해` 중복과 번역투 피동 제거**: 한 문장에 `~를 통해`가 두 번 이상 겹치거나, `~되어진다`, `~로 보여진다`, `~에 의해 ~된다` 같은 이중 피동이 쓰이지 않았는가?
- [ ] **6. 동사 부풀리기 축약**: `검사를 수행한다`, `조사를 진행한다`, `수정을 완료한다`를 `검사한다`, `조사한다`, `수정했다`로 줄였는가?
- [ ] **7. 양극단 어휘 교정(글 종류별)**:
  - 저급 AI 상투어(`다양한`, `체계적인`, `다각적인`, `유기적인`, `획기적`, `극대화`, `제고`, `도모`)를 구체적인 수치나 동작으로 바꿨는가?
  - 보고서와 설계 문서에서는 억지 순화어(`로그를 세는`, `시간을 재야 한다`, `비용이 붙는`, `고객 자료`, `사람의 시간`, `강한 비교군`)를 실무 어휘(`집계하는`, `측정해야 한다`, `발생하는`, `고객 정보`, `담당자 투입 시간`, `경쟁력 있는 비교 기준`)로 바꿨는가?
  - 대화 답변, 고객이 읽는 룰 설명, 화면 문구에서는 읽는 사람이 바로 알아듣는 쉬운 말을 골랐는가?
- [ ] **8. 방어적 면책과 작업일지 삭제**: 문단 끝마다 붙는 변명(`~라는 뜻은 아니다`, `~로 일반화하지 않는다`)이나 작업 흔적(`이번 개정에서`, `feat-123`, `사용자 요청으로`, 백업 경로, 반올림 안 된 `$0.3532235`)을 모두 지웠는가?

## Part 2: Technical Reports, Design Docs, and Proposals (보고서와 설계서 8항목)

- [ ] **9. 결론이 드러나되 문장이 아닌 소제목**: 소제목이 단순 라벨(`배경`, `아키텍처`)에 그치지 않고 핵심 결정을 보여주는가? 이때 `~했다`, `~됐다`로 끝나는 완결 문장이 아니라 명사형(`수집은 자동, 차단 결정은 담당자`)이나 신문식(`장기 작업서 격차 커`)으로 썼는가? 제목 대부분을 `왜`, `무엇이`, `어떻게`로 시작하지 않았는가?
- [ ] **10. 선출현 금지**: 자체 분류 코드(`A3`), 실험 버전(`v3`), 뒷장 번호(`6-3절의 평가`)를 설명 없이 먼저 던지지 않았는가?
- [ ] **11. 구체적 상황 우선 제시**: 규칙이나 스키마를 설명하기 전에 독자가 바로 이해할 상황을 먼저 보여줬는가?
- [ ] **12. 의사결정 맥락 명시**: 왜 다른 대안 대신 이 방식을 골랐는지, 비용이나 한계는 무엇인지 함께 적었는가?
- [ ] **13. 부록과 별첨 뺑뺑이 제거**: `~는 부록 X에 둔다` 같은 문장을 지우고 핵심 수치를 본문에 넣었는가?
- [ ] **14. 용어 일관성**: 같은 대상을 부르는 이름이 처음부터 끝까지 하나로 통일되어 있는가?
- [ ] **15. Word 보고서 종결 어미**: 문장 끝을 명사형(`~함`, `~됨`, `~있음`, `~임`)으로 맞췄는가? 양식 원본의 정형 안내문만 원래 어미를 둔다.
- [ ] **16. 보고서 구어 표현 제거**: `그래서`, `봤다`, `잡힌다`, `걸린다`, `넣는다`, `막힘 없이` 같은 말하듯 쓴 표현을 `이에 따라`, `확인하였음`, `탐지됨`, `식별하였음` 같은 보고서 어휘로 바꿨는가?

## Part 3: Work Emails and Messenger Replies (업무 메일과 메신저 7항목)

- [ ] **17. 첫 2줄 결론과 용건**: 인사 다음 1~2문장 안에 결론이나 요청 사항이 나와 있는가?
- [ ] **18. AI식 인사와 끝인사 제거**: `평안하신지요`, `다름이 아니오라`, `스스럼없이 연락 주십시오`, `아래에 핵심 요약을 정리하여 공유드립니다`를 뺐는가?
- [ ] **19. 볼드체와 소제목 도배 금지**: 짧은 메일이나 메시지에 `### 1. 개요`, `- **항목**: 내용`을 넣지 않았는가?
- [ ] **20. 링크, 일정, 수치 완결성**: `[날짜 입력]` 같은 빈칸이나 `해당 문서` 같은 막연한 지시어 대신 정확한 날짜와 링크를 넣었는가?
- [ ] **21. 자연스러운 존댓말 리듬**: 모든 문장이 `~하시기 바랍니다. ~드립니다.`로만 끝나지 않는가?
- [ ] **22. 고객 메신저 말투**: 고객에게 보내는 메신저 회신을 담당자가 직접 치는 말투로 짧게 썼는가? 결론을 앞에 두고 `~습니다/~입니다`로 끝내며, 해요체(`~요`, `~어요`, `~네요`)를 쓰지 않았는가?
- [ ] **23. 보고서체 끝맺음 금지(메신저)**: `~로 판단됩니다`, `~는 확인되지 않았습니다`, `~것으로 보이며`, `모니터링하겠습니다`, `확인 부탁드립니다`를 메신저 회신에 쓰지 않았는가?

## Part 4: Web UI, Dashboards, and Tech Blogs (웹 UI, 대시보드, 블로그 8항목)

- [ ] **24. UI 내 메타 방어 배지 제거**: `[읽기용 요약]`, `[데모 화면]`, `도식의 간격은 실제 비례가 아님`, 해시값 같은 방어 문구가 없는가?
- [ ] **25. 화면은 이름과 값만**: 섹션 제목 옆 설명, 표 캡션, 행마다 붙은 설명, 화면 아래 안내 문단, 꼬리말을 넣지 않았는가? 기준값은 문장 대신 `1시간 3건, 2종`처럼 짧게 썼는가?
- [ ] **26. 코드값 노출 금지**: `BENIGN_CONTEXT` 같은 내부 코드를 화면에 그대로 내지 않고, 필요하면 한국어 이름으로 바꿨는가?
- [ ] **27. 개발자 직역투 에러와 상태 메시지 교정**: `파라미터 유효성 검증에 실패했습니다`, `유저에 의해 취소됨`을 사용자 중심 문장으로 바꿨는가?
- [ ] **28. 빈 상태와 오류 상태의 행동 안내**: 결과가 0건이거나 오류가 났을 때 원인과 다음 행동을 짧게 안내하는가?
- [ ] **29. 도식 라벨과 실제 흐름 일치**: 도식의 화살표와 단계 라벨이 본문의 실제 순서와 일치하는가?
- [ ] **30. 블로그 도입부의 홈쇼핑 호스트 말투 제거**: `오늘은 ~에 대해 깊이 있게 알아보겠습니다!`, `정답은 바로 ~입니다!`를 뺐는가?
- [ ] **31. 블로그 결론의 뜬구름 교훈 제거**: `~는 선택이 아닌 필수입니다` 대신 실제 겪은 장단점으로 끝맺었는가?

## Part 5: Detection Rule Descriptions and Change History (룰 설명과 변경 이력 4항목)

- [ ] **32. 한 줄 설명**: 무엇을 잡는지 쉬운 말로 한 줄에 쓰고 `~하여 탐지`로 끝냈는가? 마침표는 찍지 않는다. 고객 담당자가 읽는 룰이면 도메인, 경로, 필드명, `출발지 IP별 120분 내 N건` 같은 집계 표현을 빼고 상세 조건은 따로 전달한다.
- [ ] **33. 제외 조건 유지**: 설명을 줄이면서 제외 조건을 빼지 않고, 둘째 줄에 쉬운 말로 남겼는가? (예: `주기적으로 재부팅하는 백업 서버는 제외`)
- [ ] **34. 다른 룰은 이름으로**: `다른 룰에서 따로 탐지`처럼 뭉뚱그리지 않고 룰 이름을 그대로 적었는가?
- [ ] **35. 변경 이력은 두세 단어**: `신규 등록`, `설명 수정`, `삭제`, `활성화`처럼 사람이 직접 쓴 것처럼 짧게 썼는가? 작업 번호, `사용자 요청`, 백업 경로, 긴 사유 문장은 넣지 않는다.

## Part 6: 2026 Signals (2026년 최신 신호 12항목)

- [ ] **36. 대비 틀 해체**: `단순한 A가 아니라 B`, `A보다는 B`, `A가 아닙니다. B입니다.`, `A뿐만 아니라 B`를 B와 그 근거를 말하는 문장으로 바꿨는가? 대비 자체가 요점일 때만 한 번 남긴다.
- [ ] **37. 꾸민 동사 제거**: `~로 기능한다`, `~의 역할을 한다`, `~에 자리한다`, `~로서 작동한다`를 `~이다`나 구체적인 동사로 바꿨는가?
- [ ] **38. Claude 말버릇 제거**: `조용히`, `떠받친다`, `얹혀 있다`, `삼켜진다`, `자리` 은유, `두 축으로`, `결이 같다`, `층위`, `갈래`, `뼈대`, `교차 확인했습니다`, `솔직히 말하면`, 비유 동사(`박아 두다`, `얹다`, `태우다`, `물리다`)를 은유로 쓴 곳이 없는가?
- [ ] **39. GPT 말버릇 제거**: `중요한 건`, `꾸준히`, `믿을 수 있는`, `실용적인`, `더 명확하게`, `우선순위를 두다`, `진정으로`, `결정적 증거`를 실제 방법과 근거로 바꿨는가? 존댓말 글에 `응.`, `됐어.` 같은 반말이 섞이지 않았는가?
- [ ] **40. 전문직 틀 문구 제거**: `결론부터 말하면`, `한 줄 요약`, `핵심은`, `세 가지 핵심 축`, `X는 새로운 Y다`, `검증해 봅시다`를 뺐는가?
- [ ] **41. 맞장구와 끝 제안 제거**: `좋은 질문입니다`, `정확히 짚으셨습니다`, `원하시면 ~해 드릴까요?`, `필요하시면 말씀해 주세요`를 뺐는가?
- [ ] **42. 출처에 기댄 판단 제거**: 출처가 말하지 않은 내용을 `~에 따르면 ~로 확인됩니다`로 돌리지 않았는가? `확인되지 않았지만 이는 ~를 시사한다`처럼 단서 뒤에 의미를 붙이지 않았는가?
- [ ] **43. 문장 길이 섞기**: 한 문단의 문장 길이가 모두 비슷하지 않은가? 쉼표 없이 `~하고 ~하며 ~해서`로 길게 이은 문장을 나눴는가? `그리고`를 한 문단에 세 번 이상 쓰지 않았는가?
- [ ] **44. 서식 정리**: 이모지, 대화형 머리말(`답변:`, `TL;DR`), 짧은 답변의 소제목과 굵은 글씨, 본문 화살표(`→`)를 정리했는가?
- [ ] **45. 숨은 문자 제거**: 제로폭 문자, 태그 문자, 의도하지 않은 줄바꿈 없는 공백이 없는가? (검사 스크립트 `HIDDEN_CHAR`)
- [ ] **46. 한자 0건**: `發`, `對`, `件` 같은 한자 표기가 없는가? 한자어를 한글로 쓰는 것은 괜찮다.
- [ ] **47. 제목은 문장이 아니다**: 칼럼, 기사, 보고서, 블로그의 대제목과 소제목이 `~컸다`, `~개선됐다`처럼 `~다`로 끝나는 완결 문장이 아닌가? 같은 글자로 끝나는 제목이 세 개 이상 이어지지 않는가? `능력도 개선`처럼 `~도`로 앞 제목에 기대지 않고 제목 하나만 읽어도 뜻이 통하는가? (검사 스크립트 `HEADING_SENTENCE`, `HEADING_UNIFORM_ENDING`, `HEADING_LEANS_ON_PREVIOUS`)

## Part 7: Late 2026 Signals (2026년 하반기 신호 11항목)

- [ ] **48. Claude "중요" 틀 제거**: `이게 중요합니다`, `왜 ~가 중요한가`, `~가 중요한 이유`를 결과를 말하는 문장(`이 값이 틀리면 알림이 안 간다`)으로 바꿨는가?
- [ ] **49. "그 이상" 틀 제거**: `단순한 A 그 이상입니다`, `A 그 이상의 B`를 실제로 하는 일로 바꿨는가?
- [ ] **50. 서두와 최상급 정리**: `앞으로를 보면`으로 여는 문장을 지웠는가? 한 문단에 `가장`, `최고의`, `최적의`를 세 번 이상 쓰지 않았는가?
- [ ] **51. 친절 상투 문구 제거**: `도와드릴 수 있습니다`, `도움이 되셨길 바랍니다`를 뺐는가?
- [ ] **52. GPT 선긋기 제거**: `~를 입증하지는 않는다`, `~라고 단정할 수 없다`, `~와 혼동해서는 안 된다`, `~로 봐야 한다`, `또 다른 차원`, `~을 제공할 수 있다`를 사실을 말하는 문장으로 바꿨는가?
- [ ] **53. 혼자 묻고 답하기와 부정 겹치기 제거**: `원인은? 설정 누락이었다.`, `A도 아니고 B도 아니다. C다.`를 평서문으로 바꿨는가?
- [ ] **54. 개수 예고, 지어낸 개념, 흐린 출처 제거**: `이유는 세 가지입니다`, `자동화의 함정`, `전문가들은`, `업계에서는`을 지우거나 실제 내용과 출처 이름으로 바꿨는가?
